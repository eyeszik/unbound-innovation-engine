# UNBOUND INNOVATION ENGINE v3.0

A working Python application for adaptive innovation: four independent creative workers, mechanism diversity review, recursive synthesis, optional evidence research, deferred evaluation and a validated report. Based on the supplied [master contract](docs/contracts/UNBOUND_v3.md) and [agentic blueprint](docs/contracts/AGENTIC_BLUEPRINT.md).

**Live inference requires your configured provider credentials. Mock mode is an explicitly labeled offline demonstration, not a successful live model run.**

## Quick start

Python 3.11+ (verified locally with 3.12). From this repository:

```bash
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.lock
pip install --no-deps -e .
cp .env.example .env
```

Edit `.env` on the server, never in chat. Select `UNBOUND_PROVIDER=openai`, `anthropic`, or `compatible`; supply the corresponding API key and supported model ID. For Anthropic, set an available Anthropic model explicitly. Compatible endpoints also need `UNBOUND_BASE_URL` and `UNBOUND_API_KEY`. Do not enable LangSmith tracing unless you intentionally want run inputs sent to that service.

For an offline demonstration, explicitly set `UNBOUND_PROVIDER=mock` and `UNBOUND_MODEL=mock-v1`. These deterministic fixture outputs demonstrate software behavior, not creative model quality.

Start **both** processes in separate terminals:

```bash
.venv/bin/python -m unbound.worker
.venv/bin/uvicorn unbound.api:app --host 127.0.0.1 --port 8000 --no-proxy-headers
```

Open **http://127.0.0.1:8000**. Enter a brief, choose AUTO/GENERAL/VENTURE/HYBRID, and start. The dashboard polls progress and creative-worker events, retains the run ID in its URL, shows partial results, and exports JSON and Markdown. History survives refresh/restart. The first exploration can require many model calls; budget and provider quotas remain your responsibility.

## Behavior and contracts

- LangGraph enforces the ten ordered phases. Four generation calls run concurrently with disjoint groups of three lenses; no research or scoring is passed to divergence.
- Defaults: 35 distinct retained raw ideas (40 initial candidates), five wildcards, five hybrids, three meta-hybrids, five shortlisted concepts. All 12 primary lens families are covered. Configurable counts remain inside the contract ranges.
- Each first-order hybrid has 3–4 raw parents; each meta-hybrid has 2–3 hybrid parents. IDs remain stable across retries, including gaps from rejected candidates.
- Novelty review applies the domain filter and venture banlist, records exclusions and conceptual differentiation, and repairs count/coverage. Conservative text similarity supplements model review. Neither structural tests nor an LLM can prove global originality; human semantic review remains necessary.
- GENERAL forbids unsolicited monetization. VENTURE requires buyer, purchased outcome, payment model and value defense. HYBRID assigns the relevant rubric per candidate and explains normalized weighting.
- The evaluator assesses all eligible raw/hybrid/meta candidates once; wildcards refer to existing raw concepts. Composite arithmetic is computed in Python. An explicitly justified unconventional candidate is retained even if that overrides pure score order.
- Confidence is `UNVALIDATED` without retrieved evidence, a defined outcome/horizon, assumptions and uncertainty. No numeric adoption probability is generated by the schema. Profit scores are qualitative assessments, not market facts.
- Exa is optional through `EXA_API_KEY`. Missing research is marked unavailable; DISABLED skips it. Retrieved source text is evidence for review, not proof. Wolfram's optional adapter uses `WOLFRAM_APP_ID` for explicit configured computation queries; see API configuration.
- Proposed execution blueprints never execute code, deploy services or make purchases.

## API

Owner-protected endpoints (loopback only without a password):

| Endpoint | Purpose |
|---|---|
| `POST /runs` | Accept durable job; returns 202 and run ID |
| `GET /runs` | Recent 50 runs |
| `GET /runs/{id}` | Status, phase outputs and worker events |
| `GET /runs/{id}/results` | Partial/final structured run and Markdown |
| `POST /runs/{id}/retry` | Resume a failed run from committed phases |
| `GET /runs/{id}/export.json` | Download structured results |
| `GET /runs/{id}/export.md` | Download nine-section report |
| `GET /health` | API liveness and configured provider identity |

```json
{"input":"Rethink neighborhood libraries", "configuration":{"mode":"GENERAL","research":"AUTO","idea_count":35,"hybrids":5,"meta_hybrids":3}}
```

Configuration also accepts the master prompt's novelty target, automation priority, risk tolerance, output detail, time horizon, budget, technology stack and target market. These contextual options are passed to agent prompts. Optional `computation_queries` accepts up to three explicit mathematical questions for Wolfram during evidence review; omitted by default. Set `UNBOUND_PUBLIC_ORIGIN=https://your-owned-hostname` behind TLS termination. Missing live credentials return 503 before queueing. Invalid input returns 422. Unknown runs return 404; retrying a nonfailed run returns 409. A completed run means structural validation passed, not empirical validation of its ideas.

## Persistence and recovery

SQLite stores job configuration, input hash, version, model/provider identity, phase outputs, stable concept IDs, recursive lineage, evidence, scores, events and timestamps. LangGraph checkpoints are stored separately. Each model operation has a stable cached key; each phase commits transactionally. A database lease prevents two workers executing the same run concurrently. Lease renewal occurs every 10 seconds; after a hard interruption, another matching provider/model worker can reclaim the run after 60 seconds. Failed runs require explicit retry; graceful worker interruption requeues the run.

Provider calls default to a 120-second timeout and three attempts with bounded exponential backoff. Schema and semantic contract failures retry. Count/coverage repair is also bounded. After exhaustion, the run fails honestly with sanitized stage diagnostics; previous committed outputs remain. Remote model calls may be repeated if a process dies before caching the response; exactly-once billing cannot be guaranteed. Durable concept persistence is idempotent.

`GET /health` does not prove worker availability or provider connectivity. A queued run requires a matching worker; inspect worker service logs and configured provider/model if it remains queued. PostgreSQL is deferred; do not share SQLite files across network filesystems.
